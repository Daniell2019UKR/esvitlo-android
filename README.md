# єСвітло для Android

Нативний застосунок на Kotlin і Jetpack Compose з Material 3 Expressive. Потрібен Android 8.0 (API 26) або новіший.

## Встановлення

Завантажте APK з [GitHub Releases](https://github.com/Daniell2019UKR/esvitlo-android/releases/latest) та відкрийте його на телефоні. Починаючи з версії 1.7.1, публічні APK підписуються окремим ключем релізу.

**Перехід із 1.7.0 або старішої версії.** Запишіть свої локації та черги, видаліть старий застосунок і встановіть APK зі сторінки релізу. Android вимагає перевстановлення через зміну підпису та видаляє локальні дані старої версії.

Під час першого запуску виберіть регіон і чергу. Там само можна ввімкнути сповіщення. У вкладці «Параметри» можна змінити вибір, тему, частоту синхронізації й відкрити посилання на оператора, сайт, GitHub і Telegram-бота.

Застосунок показує добові графіки на сьогодні й завтра за київським часом. Регіон і черга зберігаються на телефоні. Завантажений графік залишається доступним без мережі до завершення відповідної доби. Стани «Світло є», «Відключення» і «Немає даних» відображаються окремо. Червона картка показує повідомлення оператора, якщо воно доступне.

Графіки надходять із публічного [API єСвітло](https://github.com/Daniell2019UKR/esvitlo/blob/main/docs/api.md) через HTTPS. У відкритому застосунку графік перевіряється кожні 30 секунд за замовчуванням. У параметрах можна вибрати 30 секунд, 1, 2, 5, 10, 15, 30 хвилин або 1 годину. Потягніть графік униз або натисніть «Оновити», щоб перевірити графік одразу. Дати показано у форматі `дд-мм-рррр`, а довге попередження оператора розкривається кнопкою «Читати далі».

Кнопка «Усі черги регіону» під особистим графіком відкриває список черг поточної локації на вибраний день. Кожен інтервал відключення має окрему комірку. Черга локації позначена рамкою та підписом «Моя черга».

## Оновлення застосунку

єСвітло перевіряє останній стабільний реліз GitHub під час відкриття, до одного разу на добу після успішної перевірки. У «Параметрах» кнопка «Перевірити оновлення застосунку» розташована над частотою синхронізації. Якщо доступна нова версія, кнопка «Відкрити на GitHub» веде на сторінку релізу, де можна завантажити APK і вручну підтвердити встановлення в Android.

Після першого запуску WorkManager планує фонову перевірку приблизно кожні 6 годин. Android може відкласти її. Новий реліз також надходить через FCM. Сповіщення показується один раз для кожної версії та відкриває сторінку релізу. Режим сповіщення про оновлення можна змінити в «Параметри → Типи сповіщень → Оновлення застосунку».

## Wear OS

Версія для годинника працює від Wear OS 3 та отримує графіки напряму з того самого API. Виберіть регіон і чергу на годиннику. Головний екран показує поточний стан за графіком, час кінця інтервалу, графіки на сьогодні й завтра та попередження оператора. За відсутності зв’язку доступний збережений графік, якщо він ще діє.

Зберіть APK для перевірки командою `./gradlew :wear:assembleDebug`. Команда `./gradlew :wear:bundleRelease` створює окремий AAB для дорожки Wear OS у Google Play. Для публікації підпишіть його зареєстрованим ключем завантаження.

## Тема

Локації додаються у «Параметри → Мої локації». Кожна має назву, регіон, чергу й окремий перемикач сповіщень. На екрані графіка є до трьох кнопок швидкого перемикання. Для чотирьох і більше локацій повний список відкривається кнопкою «⋯». Загальний перемикач дозволяє призупинити всі сповіщення. Під час додавання віджета виберіть його локацію.

За замовчуванням застосунок повторює світлу або темну тему Android. У меню «Тема» можна вибрати власний режим. На Android 12+ палітра береться із системи. На Android 13+ іконка підтримує системне тонування, коли ввімкнено тематичні іконки й launcher підтримує їх.

## Сповіщення та віджети

У «Параметри → Нагадування про світло» можна окремо налаштувати час нагадувань до планового відключення та відновлення. Введіть до 10 значень від 1 до 180 хвилин через кому, наприклад `60, 15`. У редакторі локації порожнє поле успадковує загальне налаштування, а 0 вимикає цей тип нагадувань для локації. Режим звуку можна вибрати окремо для кожного типу. Точний час залежить від дозволу Android на точні будильники й актуальності графіка.

Якщо оператор підтримує адресний пошук, у редакторі локації можна ввести населений пункт, вулицю й номер будинку та підтвердити запропоновану чергу. Також можна вибрати чергу вручну.

Застосунок зберігає адресу локації на пристрої. Її можна змінити або прибрати в параметрах локації.

Увімкніть «Сповіщення про зміни графіка та попередження» в застосунку. єСвітло повідомляє про зміни графіка для вибраної черги, публікацію графіка на завтра та попередження оператора. Android 13+ запитає дозвіл.

APK із GitHub Releases отримує push через Firebase Cloud Messaging. Сервер надсилає повідомлення після виявлення зміни. Канали графіків прив’язані до регіону й черги, а попередження оператора — до регіону. WorkManager у цій збірці оновлює віджети.

У «Параметри → Типи сповіщень» окремо виберіть «Зі звуком», «Без звуку» або «Вимкнено» для змін графіка, публікації графіка на завтра, аварійних і екстрених відключень та зняття попередження. Ці режими діють для всіх локацій зі сповіщеннями. Спільне попередження про аварійні й екстрені відключення приходить один раз, у найгучнішому з двох вибраних режимів.

Додайте віджет «Сьогодні й завтра» (4×2) з меню лаунчера. Він показує по одному рядку на день, час першого відключення та кількість додаткових інтервалів, чергу й значок попередження оператора. Кольори на Android 12+ використовують системну палітру Material You.

Віджети використовують регіон і чергу застосунку. У фоні WorkManager планує перевірку кожні 15 хвилин. Android може відкласти її через економію батареї або відсутність мережі.

## Збірка

Для збірки з push завантажте клієнтську конфігурацію Firebase для `ua.pp.yesvitlo` у `app/google-services.json`. Цей файл ігнорується Git. Збірка без нього використовує локальні сповіщення за результатами опитування. Серверний ключ зберігається на сервері. [Налаштування серверного FCM](https://github.com/Daniell2019UKR/esvitlo/blob/main/docs/deployment.md#push-для-android)

Відкрийте корінь репозиторію в Android Studio з JDK 17 та Android SDK 36. Для локального APK виконайте `./gradlew :app:assembleGithubDebug` (у Windows використовуйте `gradlew.bat`). Для публікації зберіть GitHub APK через `:app:assembleGithubRelease` або Google Play AAB через `:app:bundlePlayRelease`.

На Windows використовуйте шлях до проєкту без кирилиці. Під час першої збірки Gradle завантажить залежності з Google Maven і Maven Central.

Підпишіть GitHub APK через Android SDK `apksigner` постійним ключем релізу. Для Google Play підпишіть AAB зареєстрованим ключем завантаження. Щоб оновлювати наявні GitHub-інсталяції через Play зі збереженням даних, налаштуйте в Play App Signing той самий ключ підпису застосунку, яким підписані GitHub APK. Зберігайте ключі й паролі поза Git.
